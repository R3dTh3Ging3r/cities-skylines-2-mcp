## Delivered workflow and boundary

`cs2_transit_status` inspects one exact versioned line in the caller-observed world, returning bounded waypoint/segment facts and immediate stop ownership/mode/purpose/XYZ. `cs2_transit_capabilities` describes this partial reader and unavailable dimensions. No city discovery, query allocation, route creation/editing, helper-derived load, recursive owner search or pagination. Existing legacy transit tools retain fields and behavior.

Useful results: show which waypoint/connection or segment ref is missing/recycled/deleted, where each surviving waypoint/stop is in XYZ, which owning asset/attached road it directly references, which segments have negative/nonfinite/missing distance, and whether a complete finite nonnegative candidate length is available. These are diagnostic evidence, never proof of native route validity, dispatch readiness, traversability or lane connectivity.

## Strict wire contract

Status GET:
`/v2/transit/status?bootId=<1..128>&epoch=<safeNonnegativeInteger>&line=<positiveInt>:<positiveInt>[&mode=bus|tram|metro|train|airplane][&purpose=passenger|cargo]`

- Reject missing/duplicate/unknown fields, malformed escapes, index/version overflow, unsafe epoch, empty filters, unsupported aliases and arbitrary limit/cursor/include options. Query bound4096 bytes; a canonical Node encoder and shared managed parser enforce the same contract.
- Tool input and O7 `transit.selectedLine` args are the same strict shape: `{line:{world:{bootId,epoch},index,version},mode?,purpose?}`. `line` is the FULL shared EntityRef retaining the caller-observed WorldRef. Reject index/version-only inputs. Never infer or replace an entity world from current/group world, including when expectedWorld is omitted. The compact GET bootId/epoch+line syntax is transport encoding of that full ref only.
- Before any O7 item dispatch, validate the selected EntityRef world equals the ready group world captured at admission; also reject conflicts with explicit expectedWorld. Malformed args reject the entire group atomically; a historical reference world mismatch refuses admission with zero reader calls and zero retained slots. At dispatch the common typed transit reader validates the stored original world again, and publication rejects intervening loads. Unknown keys/values reject before group dispatch. GET and O7 produce identical typed observations.
- Mode is a filter on observed `TransportLineData.m_TransportType`; only exact source-supported native values map to public names, unsupported enum stays unknown. Purpose filter tests observed prefab `m_PassengerTransport/m_CargoTransport`; do not guess from names or stop types. A proven mismatch returns zero items/matched0 only when all requested filter facts are available. If any requested filter's required native facts are absent or unknown, return the selected diagnostic item with `filter={state:"unverifiable",reasons:[...]}`, matched=null and explicit filterUnverifiable warning; it is not an excluded match. Unverifiable takes precedence over a different filter's known mismatch. With no filters, missing facts do not prevent selected-root inspection.
- Root must exist with full Index+Version, `Game.Routes.Route`, `TransportLine` and nondeleted/nontemporary status. Missing/recycled root returns structured404, wrong kind400, world mismatch409/readiness503. Missing route buffers produce an incomplete typed diagnostic entry rather than speculative reconstruction.

Response is `Observation<TransitPage>`; `TransitPage={scope:"explicitLine",requestedLine,items:[TransitLineView]|[],returned:0|1,matched:0|1|null,filter:{state:"notRequested"|"matched"|"excluded"|"unverifiable",reasons:string[]},nextCursor:null,truncated:false,capabilities}`. `matched=null` is required for an unverifiable requested filter. `truncated=false` applies to line-item selection; nested `completeness` describes route buffers separately. No fake cursor.

Selected view:
- `entity,assetKey,assetKeyReason,owner,ownerReason,routeNumber:number|null,mode:string|null,modeReason,purpose:"passenger"|"cargo"|"mixed"|"unknown",purposeFlags:{passenger:boolean|null,cargo:boolean|null},purposeReason`. mixed/unknown are documented partial-T1 extensions to avoid inventing a single passenger/cargo purpose when both/neither/unavailable prefab flags are observed. Native false/false is represented unknown with reason noTransportPurposeFlag; absence stays nullable rather than false.
- `name=null/nameReason="labelReaderNotBounded"`, `active=null/activeReason="lineActiveReaderNotVerified"`, `vehicles=null/vehiclesReason="boundedFleetReaderUnavailable"`.
- `load={kind:"passengers"|"cargo"|null,value:null,capacity:null,unit:null,occupancyRatio:null,reason:"boundedLoadReaderUnavailable"}`; mixed/unknown purpose gives null kind. No raw cargo unit guess.
- `completeness={state:"complete"|"incomplete",waypointCount:number|null,segmentCount:number|null,readWaypoints:number,readSegments:number,reasons:string[]}`.
- `waypoints:[{order,entity,exists,connection:EntityRef|null,connectionState,position:Point3|null,positionReason,waitingPassengers:number|null,waitingReason,stop:StopFacts|null,issues:string[]}]`.
- StopFacts is fixed-size: `entity,position,positionReason,owner,ownerReason,attachedParent,attachedParentReason,isAttachedToEdge:boolean|null,mode,purposeFlags,active:boolean|null,activeReason,outsideConnection:boolean`. Owner is immediate owner, not claimed platform/station role. Do not traverse connected routes or owner chains.
- `segments:[{order,entity,exists,rawDistance:number|null,distanceReason,issues:string[]}]`. Nonfinite numbers never appear in JSON; `rawDistance=null/distanceReason="nonfiniteNativeDistance"`. Finite negative rawDistance is retained as evidence.
- `health={state:"invalid"|"unknown",reasons,brokenWaypoints:EntityRef[],invalidSegments:EntityRef[],rawLength:number|null,lengthUnit:null,lengthUnitReason:"nativeSegmentDistanceUnitNotVerified",lengthValidation:"finiteNonnegativeSegmentsOnly",nativeValidity:"unknown",nativeValidityReason:"committedRouteFixtureNotRun",assessment:"structuralFactsOnly"}`. Invalid means a directly observed missing/deleted/recycled required ref or negative/nonfinite segment fact; it does not claim native UI invalid state. With no observed fault, state stays unknown rather than valid. Segment/waypoint cardinality differences are reasons, not proof of invalidity until installed semantics are checked. Incomplete/missing-stop/negative/nonfinite/missing-distance observations force rawLength=null. A finite nonnegative complete sum retains the **raw PathInformation.m_Distance unit**, which is unknown here. Do not name it lengthMeters or borrow metre qualification from the different legacy UITransportLineData.length source. Finite/nonnegative validation proves neither the unit nor native accepted path evidence. Initial M4 explicitly excludes a route-length metric.
- `candidateDuplicates=null/candidateDuplicatesReason="discoveryUnsupported"`, dispatch fields unknown. Capabilities separately describe exact read versus discovery/load/nativeValidity/preview/create/edit. No global unsupported declaration should imply legacy capabilities changed.

Capability GET: `/v2/transit/capabilities`, no query/body. Tool input empty. Return fixed source-qualified capability data: explicitLineRead partial; supported modes sourced from the already-known bus/tram/subway/train/airplane types; purpose support means reading prefab flags only. State no discovery/pagination/fleet/load/dispatch/native validity and `nativeVerification="transit-readback-v1:notRun"`. Both capability/status routes classify read in EndpointCatalog. A fixed `transit.capabilities` O7 entry is optional; status binding is required.

## Native adapter and exact work bounds

Create `Transit/NativeTransitReader.cs` or a thin native partial handler; keep raw bounded facts/contracts/policy under `Transit/` linked into core tests. All native reads occur on the game thread and validate shared world before reading, before publication and around native sampling. Capture actual start/end frames and UTC; preserve non-atomic/current-source warnings.

Hard limit **128 total entries = waypointCount + segmentCount** (bridge safety limit, not native restriction). Read buffer presence and lengths before any element access. If either buffer missing, no element traversal; return incomplete reasons. If sum exceeds128, return incomplete with counts and empty waypoint/segment arrays, reasons `routeBuffersExceedDiagnosticBudget`; no silent prefix, fake total length or cursor. Valid sources within cap are fully inspected exactly once; at most one connected-stop metadata projection per waypoint. Repeated stop refs may be memoized within this read only, never persisted across frames/worlds. No recursion or second buffer traversal to discover other lines. Max128 total fact entries bounds arrays and per-entry fixed lookups; calculate an explicit constant component-check/read budget from final adapter rather than promising2ms execution.

Source-backed root lookups: `PrefabRef.m_Prefab`, prefab `TransportLineData.m_TransportType/m_PassengerTransport/m_CargoTransport`, `Owner.m_Owner`, optional `RouteNumber.m_Number`. Resolve prefab name only via existing `PrefabSystem.GetPrefab<PrefabBase>`; bound name256 characters, otherwise null/reason. Avoid `NameSystem.GetRenderedLabelName` because its internal work is not source-bounded here.

For each `RouteWaypoint.m_Waypoint`: validate full entity, Deleted/Temp, then `Connected.m_Connected`, `Game.Routes.Position.m_Position`, optional `WaitingPassengers.m_Count`. Existence/validity checks also apply to connected stop before access. Read `TransportStopData` flags/mode through its prefab, `Game.Objects.Transform.m_Position`, immediate `Owner.m_Owner`, `Attached.m_Parent`, `TransportStop.m_Flags & StopFlags.Active`, `OutsideConnection` marker. Missing components stay null with fixed reasons. Stop activation is not line activation. Negative waiting count is null/invalid-native-value, never clamped to zero.

For each `RouteSegment.m_Segment`: validate full entity/Deleted/Temp, read `Game.Pathfind.PathInformation.m_Distance` when present. Do not invoke `BuildTransportLine`, `GetRouteVehiclesCount`, global queries or read `PathElement` contents. Optional `PathTargets` evidence can wait; do not project “ready” because temporary-to-committed semantics remain unverified.

Output bounds: <=128 fact entries, <=128 refs per fault list, bounded fixed reason strings and one root assetKey<=256. Fix a per-reader declared bound <=256KiB and verify worst-case production serialization against O7's256KiB item limit. O7 still enforces actual byte limits and per-group4MiB. GET must enforce the same output limit/error instead of gaining unbounded diagnostics. Single line per observation means O7 can schedule a multi-line set with shared budgets/world semantics.
