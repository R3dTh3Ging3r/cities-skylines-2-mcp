# Precise construction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver exact zoning, validated network changes, complete facility previews and supported asset lifecycle operations for roadmap R04, R05A/B, R07A/B and R10.

**Architecture:** Keep ECS adapters in the mod and pure selection/geometry/contracts under `CS2MCP.Bridge/Core/`. New construction commands use the foundation operation registry, writer lease, bounded scheduler and verified receipts; existing tool names remain adapters. Gate each native integration independently and publish unsupported outcomes rather than substituting an unsafe implementation.

**Tech Stack:** Existing C# 9/net472 mod, Unity ECS/game assemblies, Node >=18/TypeScript, `node:test`, shared net472 console test runner.

**Spec:** [Bridge improvement delivery design](../specs/2026-10-11-bridge-improvements.md); [roadmap](../../BRIDGE-ROADMAP.md).

## Global Constraints

- Windows and Steam Cities: Skylines II; C# 9 / .NET Framework 4.7.2 for the mod; Node >=18 and the existing TypeScript ES2022/Node16 build target. Do not raise runtime floors in these releases.
- Use existing runtime dependencies. Node tests use `node:test`; pure C# regression tests use a small .NET Framework 4.7.2 console runner with linked production sources and no game assemblies. Keep existing reference-assembly package version 1.0.3.
- All game/ECS reads and writes stay on the game thread. A batch performs sequential mutations, never parallel native construction.
- Preserve existing tool names and legacy success fields; add explicitly versioned contracts and documented deprecations. Correct false descriptions now; do not silently change a legacy field's unit or meaning.
- Keep the listener on loopback. No remote hosting, client allowlist expansion, or automatic machine-configuration edits are part of this plan.
- Compile the mod with `-p:SkipDeploy=true`. Deployment requires the game closed, a verified candidate, installed-build readback and a rollback copy.
- Native tests use a disposable city and a separately named verified checkpoint. Do not use the player's developed city as a test fixture.
- Keep raw game data, screenshots, saves, binaries, credentials and machine paths in ignored `.local/` paths. Use compact run IDs and paths below 240 characters.
- Preserve upstream history, attribution and unrelated work. Use focused `codex/` branches in the personal fork. No upstream messages or PRs without user instruction.
- A timeout is an unknown outcome, not cancellation; a successful placement, connected graph, good appearance and working service are separate checks.

## Review Focus

1. Road reconstruction or save reload recycles an apparently valid cell/entity: reject stale targets and preserve the new world (C2/C3 tests `ReloadInvalidatesPreview`, `RebuiltBlockRejectsSelection`).
2. Zero flags, opposite traffic direction or an incompatible overlay silently erases another upgrade: preserve unrelated bits and reject conflicts without charge (C4 tests `RemoveLastOverlay`, `OppositeSidePreserved`, `IncompatibleOverlay`).
3. A nearby surface segment captures a tunnel end, or a bowed curve enters a query with its midpoint outside: respect explicit 3D targets and geometric intersection (C1/C5 tests `BowedCurveIncluded`, `StackedNetworks`).
4. Cancel, validation failure or player takeover leaves preview objects/charges behind: clean temporary state, reconcile effects and release the writer (C2 fixture `PreviewCancelAndTakeover`).
5. Moving/removing an owner-linked object loses stored material, extensions or transit identity: verify preservation or reject before apply (C7/C8/C9 fixtures `PreservedState`, `AreaOwnerPreserved`, `StopRoutePreserved`).
